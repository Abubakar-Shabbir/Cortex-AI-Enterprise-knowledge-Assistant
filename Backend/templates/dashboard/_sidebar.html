{% comment %} THE sidebar — the single reusable nav shell for every authenticated page in the app (base.html includes this unconditionally; see that file's comment for why). There is no second sidebar variant to keep in sync and no visual/layout change when navigating between "workspace" and "admin" pages - only which items render changes. Workspace/Insights items are gated per pages.* (or, for Queries, queries.view_all_logs) permission the viewer's role holds. The whole Administration group is gated on can_view_admin_area (RAG.services.permission_service.has_admin_area_access - true for the Admin role, or for any role holding at least one admin-area permission); a plain workspace role with none of those still never sees it. Each item inside the group is then gated on its own specific permission, so a role holding e.g. only "system.view_health" sees the group header but only the System Health link. Active-item highlighting reuses active_nav (context_processors.breadcrumbs()), populated on every authenticated page render. h-dvh (dynamic viewport height) alongside inset-y-0, not instead of it: a `position: fixed` element pinned only via top:0/bottom:0 is what was making this sidebar look a different height per page - on a page whose content is short enough to fit without scrolling it renders at the expected full height, but on a page tall enough to require scrolling, mobile Safari/Chrome collapse their address bar as the user scrolls, which resizes the *layout* viewport those fixed offsets are computed against mid-scroll - the classic "fixed sidebar changes height as you scroll a tall page" mobile bug. h-dvh pins it to the actual current viewport instead and isn't affected by that toolbar collapse; inset-y-0 stays as a harmless no-op fallback for browsers that don't understand dvh yet. {% endcomment %}
